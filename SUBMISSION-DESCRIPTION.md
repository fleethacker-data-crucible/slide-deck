## Problem
The Fleet needs capabilities that give time back to Sailors, reduce watchstander burden and keep working when the link drops. Today, on a locked-down Navy workstation, almost none of the tools that would help can be installed: no admin rights, no Node, no Python, no git.exe, application control that blocks prebuilt binaries, and connectivity that comes and goes under EMCON and DDIL. Sailors hand-transcribe forms, re-key requisitions, route correspondence by hand, consolidate tasking from email, parse hundreds of lines of OPTASK text to find their own events, walk CASREPs around the ship for chop, and keep records programs that need a full-time manager nobody has. At the same time, future ships will run many AI systems side by side, built independently, sharing actuators and sensors, with nobody arbitrating when two of them disagree. The measured burden is hours per week per command in paperwork and re-keying, and, for the AI case, the number of consoles a watchstander has to merge in their head and the time it takes to notice a conflict, decide, and stop a misbehaving agent.

## Solution
Data Crucible is one suite of nineteen Sailor-built tools in a single GitHub organization, plus Bridge Warden, a governance layer for shipboard AI. Every tool runs from a double-clicked .bat on Windows PowerShell 5.1 and an Edge or Chrome browser, with nothing installed, no admin rights, no cloud dependency, and a server that binds to 127.0.0.1 only. Engines ship as C# source compiled in memory at start. Tools hand work to one another as plain, versioned JSON and CSV files on the local disk, never over a network. Three shared services sit under every app: Fairlead, the model router (one local address for every model, local engines first, a durable log of who asked what of which model, a private route that never leaves the PC); Lazarette, the encrypted vault (keys by item name, so no app ever holds a cloud key); and Bridge Warden, which decides what an agent may do. Local models come from Phoenix LAI (Gemma 4 on the machine's own GPU through the driver's Vulkan) and Windlass (70B-class models streamed through memory one layer at a time on CPU), so the whole suite runs with the network unplugged.

Against the six use cases:
- Paperless Underway (anchor). Track A: SnapShackle captures the handwritten form, Bowerbird reads it and proposes a name and folder (propose only, journaled, undoable), Lazarette's PDF engine fills the official AcroForm or XFA form in the browser. Track B: PacketRat reads a week of exported .eml and .msg files with no Outlook needed, triages them into a human-reviewed action queue with the reason and source beside every item, drafts status updates that a person sends, hands verified actions to Halyard as backlog items and counts to a Semaphore dashboard.
- AI automated systems and MORDECAI. Bridge Warden sits between every onboard AI agent and the ship. No agent touches an actuator. Each action becomes a typed intent that Warden authenticates, checks against authority and safety limits, compares with other agents' intents, resolves or escalates to a human, executes and logs in a hash-chained ledger. Two agents asking for the same rudder is a conflict-detector case: same tick detection, the authority matrix, policy or an operator decision, and a reversible record.
- Automated message traffic extraction and OPTASK parsing. The same PacketRat pipeline: deterministic rules first, then a model through Fairlead on a strict wire protocol, Bearing citations that quote the exact source lines, a person verifying the queue, a versioned hand-off file, Semaphore timelines and dashboards, Eight Bells chronology checks against the watch log, and TalkForge speaking the next event with an on-device voice.
- CASREP Command. Draft once in the browser, route through Halyard's approval gateway (one holder, a write lease, a journal with rollback), chop as reviewed versions in Gangplank for people without Git training, release through a PacketRat draft a person sends, and track every step in the Ship's Log and a Semaphore readiness view.

## Impact (Warfighting & Deckplate)
Users are named: the expeditionary unit in the field, the command staff turning a week of tasking into an action list, the OOD and EOOW on a ship running several AI systems. PacketRat's burden record stores a hand-timed baseline per task and the timed runs after, so the minutes returned are measured by a Sailor, not estimated by a counter; its estimate counter is labeled as such. Bridge Warden, measured in simulation with five agents on a synthetic ship: 0 unsafe actions reached the actuators in the rogue-agent scenario and it was contained in about 3 seconds; evaluation round 3 put 46 of 53 actions on time with 0 hits and an 11.5-second median reaction, down from 29.4 seconds; SAFE-STOP halts every agent in a two-second hold; the watchstander monitors one console instead of one per AI system.

## Speed to Fleet
The stack is confirmed running in user context on NMCI, Nautilus endpoint devices and Nautilus virtual devices. Install is one zip with a SHA-256 beside it, unblocked and extracted, then one double-click. Everything defaults to offline; Fairlead falls back to local models when a provider or the internet is gone. Releases are MIT licensed. The one remaining gap is CANES afloat, with a dated 30/60/90 to close it. Our own ATO feasibility assessment is candid: compile-at-launch C# is blocked under Constrained Language Mode and no repo tracks an SBOM yet; the remediation (signed prebuilt engines where policy allows, an SBOM per release, one ISSM-supervised test per baseline) is scheduled before day 60.

## Scalability
Nothing is hard-coded to a ship, rating or warfare commander. Triage rules, message grammars and dashboard definitions are configuration files. Hand-off formats between tools are versioned and documented in one place. The same router, vault and warden sit under every app, so a new tool inherits model access, key handling and governance instead of rebuilding them. Agents, policies and data sources in Bridge Warden are configuration plus adapters, so it applies to any ship class or domain.

## Barriers Removed
No re-keying from mail to backlog to dashboard. Forms filled once from a capture. A CASREP that never leaves one audited store, so parts priority starts when the casualty is written. A friction log kept from kickoff with responsible organizations and recommended actions, already holding application-control policy, the absence of an authorization boundary and sponsor, classic Outlook validation on managed workstations (removed by reading .eml and .msg files), the CANES hosting path, and portal key handling.

## Human Authority & Safety
Every tool that uses a model answers the same four questions in writing. PacketRat changes mail only on a named command with --yes, replies are drafts, it never sends or deletes, and it keeps a hash-chained action log with a verify command. Halyard writes only what a person approves and only to the sandbox backlog, with a journal and rollback. Bowerbird proposes every rename and confirms in the page. Eight Bells keeps reviewer dispositions, a two-person rule on lessons and a hash-chained audit trail. Fairlead sends local context off the machine only when the user allows it. Bridge Warden enforces may-do, never-do and needs-approval per agent, escalates with a two-minute decision window, runs a periodic system check that SAFE-STOPs itself after two misses, and lets the operator pause, constrain, override, roll back or stop everything. Logs are tamper-evident, not tamper-proof, and the docs say so.
